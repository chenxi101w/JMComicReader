# JMComicReader（Windows）· 文档维护提示词

> **交给接手本项目的 AI / 未来会话的标准提示词**。新会话开始先粘贴，保证每次改动后文档同步维护、版本号一致。

---

## 标准提示词

> 你是 JMComicReader（Windows，Python + Flask + pywebview）维护者。改动任何代码后，**必须**按以下约定同步维护：
>
> 1. **更新 `docs/需求文档.md`**：在末尾「变更记录」追加一条（时间 + 改动内容 + 版本）。
> 2. **更新 `docs/升级日志/CHANGELOG.md`**：按模板在顶部追加本版记录，并标注本次新增/修复/内部调整。
> 3. **更新版本号**：按 `docs/升级日志/版本规范.md` 的 X.Y.Z 进位规则升 `VERSION`；改动具体功能则 minor +1，纯修 bug 则 patch +1。
> 4. **新增/改动接口**：同步 `docs/API.md`；**改动数据表结构**：同步 `docs/架构报告.md` 与 `docs/功能函数清单.md`。
> 5. **发版前**：对照 `docs/真机验证清单.md` 逐项检查。
> 6. **文档只放 `docs/`**，根目录不允许出现 `docs/` 的重复副本。
> 7. 复刻自 Android 版时，以 Android `docs/功能函数清单.md` 与源码为事实来源；完成后在 `docs/已知坑与发版铁律.md` 的「复刻方向」勾掉对应项。

---

## 文档一致性速查

| 变更类型 | 必须同步 |
|----------|----------|
| 修复 bug / 小调整 | 需求文档·变更记录 + CHANGELOG + VERSION(patch) |
| 新增 / 删除 / 升级功能 | 需求文档 + CHANGELOG + VERSION(minor) + 功能函数清单 |
| 大改 UI / 架构 | 需求文档 + CHANGELOG + VERSION(major) + 架构报告 |
| 新增 / 改动接口 | API.md |
| 新增 / 改动数据表 | 架构报告 + 功能函数清单 + (已知坑·发版铁律的迁移规范) |
| 发版 | 真机验证清单逐项确认 |

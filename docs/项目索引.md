## 一、这是什么

Windows 桌面漫画阅读器。Python 3.13 + Flask（本地 HTTP 服务）+ pywebview（Edge WebView2 窗口）+ SQLite + 原生 JS 前端，PyInstaller onedir 打包。

**不是网页应用**：Flask 只绑 `127.0.0.1`，窗口用 WebView2 套壳，用户看到的是一个桌面程序。

## 二、两套代码的关系（关键）

| | 路径 | 说明 |
|---|---|---|
| **桌面版（本项目）** | `D:\code\CODE\AI-Windows\jmcomicreader` | 移植的**执行方** |
| **手机版（参照物）** | `D:\code\Android\AI-Android\game\jmcomicreader` | Kotlin + Compose + Room，**移植的事实来源** |

- 手机版当前基准：**v7.3.0 / versionCode 147 / Room DB v13**（16 实体 / 15 DAO）。
- **手机版每次大版本升级后，务必重新对照** —— 桌面版的复刻清单曾按 v6.0.13 写过，很快就过时了（详见「复刻进度」）。
- 移植原则：**数据层先行**，逐模块对齐；每完成一块同步版本号 + CHANGELOG + 两份清单。

## 四、构建与发版

```bash
# 必须用项目内构建环境（托管 venv 没 Flask / 依赖不一致）
cd D:\code\CODE\AI-Windows\jmcomicreader
.venv-build\Scripts\python.exe build\_build.py
```

一次跑完做三件事（顺序固定）：
1. PyInstaller 打包到 `dist_out/JMComicReader/`（中转目录）
2. 打便携 zip 到 `dist_out/`（**prune 掉 `UserData`/`TempCache`**，否则包会膨胀到 GB 级）
3. 把 `exe` + `appdata` 部署到 `D:\Game\JMComicReader`（保留其 UserData），并删掉中转目录

> `build_out/` 是 PyInstaller 的中间产物（约 33M），删掉不影响正确性，只是下次会全量重建。
> exe 正在运行时会占住文件导致部署失败 —— 脚本会给出提示，关掉再重跑即可。

发版清单（缺一不可）：
1. 改 `VERSION`
2. 更新 `docs/升级日志/CHANGELOG.md`（按文件顶部的模板格式）
3. 写 `dist_out/JMComicReader_vX.Y.Z_更新说明.md`
4. 若涉及复刻进度，同步 `docs/需求文档.md` + `docs/已知坑与发版铁律.md` 的勾选状态
5. 跑构建

## 七、硬性约束（违反会出事）

1. **绝不 drop 重建表**：数据库迁移只能用 `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ADD COLUMN`（幂等），见 `database.py:_ensure_column`。
2. **加字段优先塞 `comic_status.ext`（JSON）**，能免掉 DDL 变更（回收站标记就是这么做的）。
3. **`UserData/` 是用户数据**：构建时不清、不打进 zip；拷贝整个 `UserData/` 即完成迁移/备份。
4. **删除类操作对用户数据要留后路**：新代码优先软删（回收站），彻底删必须二次确认。
5. **改前端不用动 spec**：`datas` 已经包含整个 `web/` 目录。
6. 跑构建/测试用 `.venv-build\Scripts\python.exe`，别用托管 venv。
7. Bash 沙箱里先 `export PATH="/usr/bin:/bin:$PATH"`；**后台任务里不要接 `| tail`**（后台 shell 没继承 PATH，会让管道断掉、误报失败）。

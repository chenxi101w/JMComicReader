# JMComicReader（Windows）· 已知坑与发版铁律

> 改数据层 / 发版前必读。含发版铁律 + 已踩过的坑 + 待办/复刻方向。

## 一、发版铁律（数据安全）

1. **SQLite 表结构变更**：
   - 建表一律 `CREATE TABLE IF NOT EXISTS`，幂等。
   - **加列一律 `ALTER TABLE ... ADD COLUMN ...`** 包在 `try/except sqlite3.OperationalError: pass` 里（已存在则跳过），**绝不** drop 重建清用户数据。
   - 示例见 `core/models/database.py` 里 `downloaded_comics` 的 `chapter_count` 增量迁移。
2. **配置默认值**：新增键进 `DEFAULT_CONFIGS`，写库用 `INSERT OR IGNORE` 保留用户现有值。
3. **破坏性操作必须先列清单确认**：删数据文件、清空表、改主键等一律先与用户确认。

## 二、已知坑（已踩过，勿重犯）

- **黑名单未在搜索入口统一过滤**：搜索只过滤了书架，导致搜索页屏蔽后翻页/切回又出现。已在 `app.py` 抽出 `_filter_blocked` 统一应用（v2.4.x 修复）。
- **批量下载不限并发**：此前 `max_concurrent_downloads` 设置项一直未生效，批量下载会无限制起线程打 JM。已在 `app.py` 用全局 `ThreadPoolExecutor(max_workers=上限)` 统一调度（v2.4.9 修复）。
- **多章漫画翻页卡顿**：原每翻一页都调网络抓 JM 章节顺序。已改纯本地校验 + 进程内缓存（v2.4.5 修复）。
- **封面 / 阅读接口全量扫描**：原每次 `get_downloaded_comics()` materialize 整表只为取单本 title/cover。已改为 `ComicManager.get_comic_meta()` 单条查询（v2.4.9）。
- **搜索结果标签消失**：是「标签按需补全没接线」导致，已接 `/api/search/enrich` 并扩展推荐页作用域（v2.4.7 ~ v2.4.11）。
- **GBK 编码崩溃**：Windows 中文系统默认 GBK，jmcomic 打印含特殊字符（如 ♡）时崩溃。已在 `desktop_app.py` 启动时强制 UTF-8（`configure_utf8_output`）。
- **WebView2 缺失打不开**：需 Edge WebView2 运行时，`desktop_app.py` 已做窗口失败回退浏览器兜底。
